# Техническое задание на разработку программного продукта для планирования встреч
## Команда: Звезда смерти

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2\. Декомпозиция задачи

### 2.1 User stories

#### Аутентификация

1\. Как сотрудник, я хочу зарегистрироваться, чтобы получить доступ к приложению

2\. Как сотрудник, я хочу войти в систему, чтобы пользоваться приложением (своим расписание, приглашениями и т.д.)

3\. Как сотрудник, я хочу выйти из аккаунта, чтобы безопасно завершить работу

#### Профиль

1\. Как сотрудник, я хочу просматривать свой профиль, чтобы убедиться, что данные корректны

2\. Как сотрудник, я хочу редактировать профиль, чтобы коллеги видели актуальную информацию обо мне

#### Встречи

1\. Как организатор, я хочу создать встречу с выбором даты и часового слота, чтобы запланировать событие

2\. Как организатор, я хочу пригласить сотрудников на встречу, чтобы они могли ответить «принял/не принял»

3\. Как организатор, я хочу видеть статусы ответов приглашённых, чтобы понимать состав участников

#### Приглашения

1\. Как сотрудник, я хочу видеть список активных приглашений, чтобы не пропускать встречи

2\. Как сотрудник, я хочу открыть приглашение и ответить «принял/не принял», чтобы сообщить о возможности участия

#### Расписание

1\. Как сотрудник, я хочу просматривать своё расписание по дням, чтобы знать план на сегодня

2\. Как сотрудник, я хочу просматривать расписание по неделям, чтобы планировать нагрузку

3\. Как сотрудник, я хочу просматривать расписание по месяцам, чтобы лучше понимать свою занятость

### 2.2 Use case

* Роль: Сотрудник компании

*  	Неверные данные.

## 3. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 4. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

### 4.1 Задачи для Backend-разработчика
* Реализовать схему БД через Liquidbase:
  * Таблицы: [users, meetings, invitations](https://dbdiagram.io/d/Android-Bootcamp-2026-zvezda-smerti-team-69790075bd82f5fce2cbd62d)
  * Ограничения: уникальность email
* Реализовать аутентификацию:
  * `POST /auth/register` - регистрация с валидацией email и пароля
  * `POST /auth/login` - вход в систему
* Реализовать эндпоинты:
  * `GET /me`, `PATCH /me` - профиль  
  * `POST /meetings` - создание встречи (валидация: начало = HH:00, проверка конфликта у организатора)  
  * `PATCH /meetings` - редактирование встречи
  * `GET /schedule/day?date=...`, `/week`, `/month` - расписание  
  * `POST /meetings/{id}/invite` - приглашение пользователей  
  * `GET /invitations` - активные приглашения текущего пользователя  
  * `PATCH /invitations/{id}` - обновление статуса (ACCEPTED / DECLINED)  
  * `GET /meetings/{id}/invitations` - статусы приглашённых (для организатора)
* Реализовать бизнес-правила:
  * Время начала встречи должно быть кратно часу  
  * Запрет создания встречи, если у организатора уже есть встреча в этом слоте  
  * Статусы приглашений: PENDING, ACCEPTED, DECLINED

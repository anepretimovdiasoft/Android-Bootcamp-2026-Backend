# Техническое задание на разработку программного продукта для планирования встреч
## Команда: 404 Not Found Team

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

## 4. User Stories

1.  **Регистрация/Авторизация:** Как сотрудник, я хочу зарегистрироваться и войти в систему, чтобы получить доступ к своему календарю.
2.  **Профиль:** Как сотрудник, я хочу редактировать свой профиль, чтобы информация обо мне была актуальной.
3.  **Создание встречи:** Как организатор, я хочу создать встречу на конкретный часовой слот и пригласить коллег, чтобы обсудить рабочие вопросы.
4.  **Ответ на приглашение:** Как приглашенный участник, я хочу видеть входящие приглашения и принимать или отклонять их (Yes/No), чтобы организатор знал о моем присутствии.
5.  **Просмотр расписания:** Как сотрудник, я хочу видеть свое расписание на день, неделю или месяц, чтобы планировать свое время.

## 5. Use Cases

### UC-1: Создание встречи
**Актер:** Сотрудник (Организатор).
**Предусловие:** Пользователь авторизован.
1.  Пользователь выбирает дату и свободный часовой слот (строго час, например 10:00-11:00).
2.  Пользователь добавляет тему встречи.
3.  Пользователь выбирает участников из списка сотрудников.
4.  Система проверяет доступность слота (опционально).
5.  Пользователь подтверждает создание.
6.  Система сохраняет встречу и рассылает приглашения.

### UC-2: Ответ на приглашение
**Актер:** Сотрудник (Приглашенный).
**Предусловие:** Есть активное приглашение.
1.  Пользователь открывает список "Активные приглашения".
2.  Пользователь выбирает встречу.
3.  Пользователь нажимает "Принять" или "Отклонить".
4.  Система обновляет статус участия в базе данных.

### UC-3: Просмотр расписания
**Актер:** Сотрудник.
1.  Пользователь выбирает режим просмотра (День/Неделя/Месяц).
2.  Система отображает сетку календаря с занятыми слотами.
3.  Пользователь может нажать на слот, чтобы увидеть детали встречи.

## 6. Задачи для разработки (Backend)

1.  **Настройка окружения:**
    *   Инициализировать Spring Boot проект.
    *   Настроить подключение к PostgreSQL/H2.
    *   Подключить Liquibase и создать стартовую миграцию.
2.  **Проектирование БД (Entity):**
    *   Создать сущность `User` (id, login, password, name).
    *   Создать сущность `Meeting` (id, topic, start_time, end_time, owner_id).
    *   Создать сущность связи `MeetingParticipant` (meeting_id, user_id, status: ACCEPTED/DECLINED/PENDING).
3.  **API (Controllers & Services):**
    *   `AuthController`: регистрация и вход (выдача токена).
    *   `MeetingController`:
        *   POST /meetings (создать встречу).
        *   GET /meetings (получить расписание).
        *   POST /meetings/{id}/respond (ответить на приглашение).
4.  **Валидация бизнес-логики:**
    *   Проверка, что слоты строго часовые (XX:00).
    *   Проверка прав доступа (нельзя редактировать чужую встречу).

# Техническое задание на разработку программного продукта для планирования встреч

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.















User Stories:
Как сотрудник, я хочу зарегистрироваться и войти в систему, чтобы получить доступ к функционалу планирования встреч.

Как сотрудник, я хочу настраивать свой профиль, чтобы другие сотрудники могли видеть мою информацию.

Как сотрудник, я хочу создавать встречи с почасовыми интервалами и приглашать других сотрудников, чтобы организовать совместные мероприятия.

Как сотрудник, я хочу видеть свои приглашения и отвечать на них (принять/отклонить), чтобы управлять своим расписанием.

Как сотрудник, я хочу просматривать свое расписание в разрезе дня, недели и месяца, чтобы эффективно планировать время.

Use Cases:
UC1: Регистрация и авторизация
Актор: Сотрудник

Предусловия: Пользователь не аутентифицирован

Основной поток:

Пользователь вводит email, пароль и данные для регистрации

Система проверяет уникальность email

Система создает учетную запись

Система аутентифицирует пользователя

Пользователь получает доступ к системе

UC2: Управление профилем
Актор: Сотрудник

Предусловия: Пользователь аутентифицирован

Основной поток:

Пользователь запрашивает данные своего профиля

Система возвращает данные профиля

Пользователь изменяет данные (имя, должность и т.д.)

Система сохраняет изменения

UC3: Создание встречи
Актор: Сотрудник

Предусловия: Пользователь аутентифицирован

Основной поток:

Пользователь указывает дату, время начала (строго по часу), продолжительность (в часах), описание

Пользователь выбирает участников из списка сотрудников

Система проверяет доступность временного слота у организатора

Система создает встречу и отправляет приглашения участникам

UC4: Ответ на приглашение
Актор: Сотрудник

Предусловия: Пользователь аутентифицирован, есть неподтвержденные приглашения

Основной поток:

Пользователь просматривает список приглашений

Пользователь выбирает приглашение

Пользователь подтверждает или отклоняет участие

Система обновляет статус приглашения

UC5: Просмотр расписания
Актор: Сотрудник

Предусловия: Пользователь аутентифицирован

Основной поток:

Пользователь выбирает период (день/неделя/месяц)

Система возвращает встречи за выбранный период

Пользователь просматривает свое расписание

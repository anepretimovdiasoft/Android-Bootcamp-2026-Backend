# Team Opit

# Техническое задание на разработку программного продукта для планирования встреч

## 1. Общие описание

Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании.
Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)

Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java**
с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий
функционал:

* **Регистрация и авторизация** сотрудника.
* **Настройка личного профиля**.
* **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны
  иметь возможность дать бинарный ответ (**принял** / **не принял**).
* **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности
  посещения.
* **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать
встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть

Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2
**.

Серверное приложение должно:

* Предоставлять API, необходимый для полноценной работы мобильного приложения.
* Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
* Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

## 4. Декомпозиция задачи (Backend)

## 4.1 Person stories

**US-1:** Как сотрудник, я хочу зарегистрироваться в системе, чтобы получить доступ к функционалу.

**US-2:** Как сотрудник, я хочу авторизоваться в системе, чтобы получить доступ к функционалу.

**US-3:** Как сотрудник, я хочу создавать встречи, чтобы общаться с коллегами.

**US-4:** Как сотрудник, я хочу отвечать на приглашения в встречи, чтобы принять или отклонить
приглашение.

**US-5:** Как сотрудник, я хочу просматривать расписание встреч, чтобы планировать встречи.

## 4.2 Use Cases

### UC-1: Регистрация пользователя

**Цель:** Создать учётную запись сотрудника в системе  
**Участники:** Сотрудник (пользователь)  
**Предусловия:** Пользователь не зарегистрирован в системе  
**Основной поток:**

1. Пользователь отправляет запрос с email, именем и паролем
2. Система проверяет что email не занят
3. Система сохраняет данные пользователя в БД
4. Система возвращает успешный ответ

**Альтернативный поток:**

1. Email уже занят
2. Ошибка: "Email уже занят"

### UC-2: Авторизация пользователя

**Цель:** Получить доступ к API системы  
**Участники:** Сотрудник (пользователь)  
**Предусловия:** Пользователь уже зарегистрирован  
**Основной поток:**

1. Пользователь отправляет email и пароль
2. Система проверяет данные в БД
3. Система генерирует JWT токен
4. Система возвращает токен пользователю

**Альтернативный поток:**

1. Неверные данные
2. Ошибка: "Неверные данные"

### UC-3: Создание встречи

**Цель:** Запланировать встречу с другими сотрудниками  
**Участники:** Сотрудник (организатор)  
**Предусловия:** Пользователь авторизован  
**Основной поток:**

1. Пользователь указывает название, дату, время начала и конца встречи
2. Система проверяет что время кратно часу
3. Пользователь выбирает участников из списка
4. Система создаёт встречу и приглашения
5. Система возвращает данные созданной встречи

**Альтернативный поток:**

1. Время не кратно часу
2. Ошибка: "Время не кратно часу"

### UC-4: Ответ на приглашение

**Цель:** Подтвердить или отклонить участие во встрече  
**Участники:** Сотрудник (приглашённый)  
**Предусловия:** Пользователь имеет приглашение со статусом "ожидает"  
**Основной поток:**

1. Пользователь выбирает приглашение
2. Пользователь выбирает "принять" или "отклонить"
3. Система обновляет статус приглашения
4. Система возвращает обновлённое приглашение

**Альтернативный поток:**

1. Приглашение уже обработано.
2. Сообщение: "Приглашение уже обработано"

### UC-5: Просмотр расписания

**Цель:** Увидеть свои запланированные встречи  
**Участники:** Сотрудник (пользователь)  
**Предусловия:** Пользователь авторизован  
**Основной поток:**

1. Пользователь выбирает период (день/неделя/месяц)
2. Система находит все встречи пользователя за этот период
3. Система возвращает список встреч

**Альтернативный поток:**

1. Нет встреч в выбранный период
2. Сообщение: "Нет встреч в выбранный период"

## 5. База данных

### 5.1 Проектирование БД

Спроектирована структура из 6 таблиц:

- **departments** - департаменты внутри организации
- **persons** - сотрудники (регистрация/авторизация)
- **meetings** - встречи (создание, время по часам)
- **invitations** - приглашения (статусы ACCEPTED/DECLINED/PENDING)
- **authorities** - роли пользователей
- **person_authorities** - связь между person & authority

Визуальная схема доступна по ссылке:  
**https://dbdiagram.io/d/meeting_planner-69834e18bd82f5fce2a21845**

## 6. Архитектура проекта

### Backend-часть

- **Java 17** + **Spring Boot 3.5.5**
- **PostgreSQL** (продакшен) / **H2** (разработка/тесты)
- **Spring Data JPA** + **Hibernate**
- **Spring Security** + **JWT** аутентификация
- **Liquibase** для миграций БД
- **Docker** контейнеризация

## 7. API Endpoints

### Аутентификация

- `POST /api/auth/register` - регистрация пользователя
- `POST /api/auth/login` - авторизация (получение JWT)

### Пользователи

- `GET /api/persons` - список пользователей (с пагинацией)
- `GET /api/persons/{id}` - информация о пользователе

### Встречи

- `POST /api/meetings` - создание встречи
- `GET /api/meetings/{id}` - информация о встрече
- `DELETE /api/meetings/{id}` - удаление встречи
- `GET /api/persons/{personId}/meetings` - встречи пользователя

### Приглашения

- `POST /api/invitations/{id}/respond` - ответ на приглашение
- `GET /api/persons/{personId}/invitations` - приглашения пользователя

## 8. Запуск проекта

### Быстрый запуск (Docker)

```bash
# Собрать и запустить все контейнеры
docker-compose up -d --build

# Приложение будет доступно по адресу:
# http://localhost:8080
# Swagger UI: http://localhost:8080/swagger-ui.html
```

## 9. Тестирование

Проект покрыт unit-тестами для критической бизнес-логики:

- Регистрация пользователя (успешная/дублирование email)
- Создание встречи (валидация времени, проверка организатора)
- Ответ на приглашения

Используемые технологии тестирования:

- JUnit 5
- Mockito
- Spring Boot Test
- H2 in-memory база
